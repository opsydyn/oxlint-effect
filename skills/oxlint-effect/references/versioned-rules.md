# Versioned Rule Guidance

Default exports target Effect 4; published 1.x remains legacy. Select `effect3`
for Effect 3, register `linteffect` once and retain existing overrides. Preset
selection is explicit policy, not proof of types or application correctness.

For each ID below, inspect the annotated failure and passing repair in its
matching pinned consumer. Consumer group READMEs document detection variants,
known alias/import/ownership limits and intentional changes to error channels.
Do not rename symbols, add casts or suppress failures to evade a detector.
A passing control labelled as a gap is not a recommended repair.

## API Selection

Current Context.Service replaces legacy Context.Tag/Effect.Service construction
where the actual consumer contract supports it. Current broad recovery uses
Effect.catch/catchEager; legacy catchAll remains legacy policy. Legacy Effect.catch
has discriminator/options arguments and is not equivalent to current broad catch.
Current Result replaces applicable legacy Either patterns. Current schema data
construction is schema .make, not the AST-level Schema.make function. Use actual
schema codec signatures, not a search-and-replace migration.

Keep mapping callbacks pure. Returning `Effect.fail` from `map`, or returning an
Effect from `gen`, succeeds with a nested Effect value: use an Effect-returning
`flatMap` or `yield* Effect.fail(taggedError)` instead. Current `mapEager` and
`flatMapEager` callbacks are checked too; a pending source defers execution, while
an already resolved source can invoke the callback during construction.

Current atoms are native effect/reactivity; legacy atom adapters require matching
Effect 3 peers. Atom effects must execute with registry provision; registry actions
must retain their deferred owner. Explicitly preserve mounted lifetime and cleanup.
Observer callbacks, expected absence, typed failures, defects and interruption
are distinct contracts. Do not turn an observer into recovery or fabricate success
as a generic repair. Type-aware engine opt-in does not type-enable custom JS rules.
