# Atom State And Platform Boundaries (Effect 3)

Q51 uses @effect-atom/atom 0.6.0, @effect/experimental 0.60.0 and @effect/rpc 0.75.0, compatible with the locked Effect 3/platform versions. No React atom adapter or client rendering is qualified here.

- `no-effect-sync-console`: five direct, regular-callback, unused-nested and multiple-console cases. One report per outer sync, recursively including unused code. Effect logging routes through an actual pinned logger and retains 42. Alias/computed/named callbacks and import order are gaps; direct console output outside sync is outside this rule.
- `no-atom-registry-effect-sync`: twelve cases cover get/set/update/modify/refresh for actual registry and Atom calls, unused nested functions and first-match granularity. Registry actions are deferred closures; do not eagerly move mutation out of sync at module construction. Atom operations already return Effects: wrapping constructs an inner Effect but does not execute it. The repaired native Effect must run with real registry provision. This deliberately fixes missing execution rather than claiming the original nested Effect was executed. Alias/computed/named callback and import-order gaps remain. Only literal Atom/atomRegistry receiver names are recognised.
- `no-family-collection-read`: six actual family definitions cover CollectionAtom/ListAtom/Visible...Atom/ResultsAtom/ReadStateAtom suffixes, get/get.get/Atom.get and first-match recursion. The extra ordinary no-import case proves there is no ecosystem gate or binding ownership. Keyed source atoms retain present/missing projections and mounted updates. Renaming a broad collection, changing the receiver or using computed family access is a detector gap, not a repair. No general performance or React subscription guarantee is claimed.

`atoms.contracts.ts` checks actual lazy mutation, get/update/modify results, inner Effect construction versus execution, logger routing and mounted projection updates. All registries are disposed and mounts released. Anti-patterns remain intentionally unfixed.

## Q52 State And Envelope Ownership

- `no-naked-object-state-update`: seven transition/rebuild/JSON warnings plus two ordinary no-import JSON controls. Ref.update/modify callback spreads, Object.assign with an empty target and three arguments, fromEntries containing entries, and every direct JSON parse/stringify are syntax policy, not semantic transition analysis. Unused nested spreads warn; curried Ref calls, aliases, computed JSON, two-argument assign and literal entries are gaps or clean shapes.
- Real repairs use Struct.evolve, immutable Record set/modify/remove and State.make with legacy Record.modify semantics and Schema.parseJson/Schema.decodeUnknownSync. Preserve wire output, return value and original state. Typed validation deliberately rejects invalid data accepted by raw JSON.parse; this strengthens the boundary rather than claiming identical acceptance. Current Schema.make is an AST constructor, not the data-construction API. Legacy diagnostic text stays unchanged.
- `no-wrapgraphql-catchall`: five legacy catchAll and flatMap warnings, including free pipe, recovery before wrapper and unused nested wrapper. The syntax scan does not prove ordering or envelope ownership. Data-first, alias and import-order controls are gaps. Legacy Effect.catch is discriminator-specific, not the current broad recovery signature; the rule deliberately leaves that targeted recovery clean.
- The local typed wrapGraphqlCall/applyResponse harness is not an external GraphQL client's API. Success retains 42; the repaired response keeps original structured error identity rather than fabricating fallback success. Failure-channel preservation is an intentional correction, not equivalence with swallowed failures. No blanket prohibition on every catch operator is claimed.

`state-envelope.contracts.ts` observes actual Ref transitions, immutable records, missing keys, wire equivalence and validation failures, successful envelopes and original failed envelope identity. `state-envelope-api.types.ts` proves removed/current API distinctions without casts in runnable controls.
